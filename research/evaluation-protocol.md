# 固定新闻识别审阅集（开发评估 v1）

本流程建立可复现、可人工审核的新闻级识别评估集。**当前只建立样本与审阅模板，没有把程序输出或模型试标冒充人工真值。** 模板初始全部为 `pending`、`labels: null`；没有合格人工审核时，评估结果必须是 `not_evaluable`，没有准确率。

## 评估范围与独立性

样本仅来自已准备的 `local-data/validation_pairs.jsonl`，允许 S016–S020。脚本不读取 S021–S030 测试输入、未来事件答案、模型预测或训练试标来选择样本。

这五个案例已用于预测模型的开发验证和参数选择。因此，即使人工独立阅读新闻，这个集合也只能称为 **development recognition evaluation（开发阶段识别评估）**，不能称为未触碰的独立测试集，更不是未来七天真实军事事件金标准。后续应另行冻结新的时间段或案例，完成独立采集与结果核验后建立真正的保留测试集。

## 固定抽样与文件

每个案例将其日历窗口分成前、中、后三个等长区间，每区间抽 4 篇，最多每案例 12 篇。使用固定 seed 与 pair ID 的 SHA-256 排序；区间样本不足时，在该案例剩余新闻中确定性补齐。该流程不使用事件关键词、模型分数或正负标签。每个案例权重相近，不能直接用这 60 篇估计整个新闻流的自然事件发生率。

- `research/evaluation-manifest.json`：固定样本 ID、时间分层、原文哈希、完整开发池哈希和抽样政策。可以进入版本控制，不含全文或人工标签。
- `local-data/evaluation/review.jsonl`：原始案例与全文、人工审核记录及最终标签。保持本机存储，被 Git 忽略。
- `local-data/evaluation/recognition-report.json`：模型版本、审阅覆盖率、未审核清单、五类任务的混淆矩阵和逐样本预测。保持本机存储。

```sh
node scripts/prepare-development.mjs
node scripts/prepare-evaluation.mjs
# 完成人工阅读和标注后再运行；全部 pending 时也可以检查 not_evaluable 状态。
node scripts/evaluate-recognition.mjs
```

重复准备不会覆盖人工审核文件。来源池或样本清单发生改变时脚本报错，不能静默重选难例。确需更换语料，应另建带理由的新版本、保留旧结果，禁止只保留让某版模型成绩更高的样本。新闻来源字段不可在审核文件中修改；哈希校验会拒绝这些变化。

## 人工标签定义

`labels` 包含五个布尔字段；不确定时不要猜 `false`，保持 `pending` 或 `needs_adjudication`，在审核备注中记录原因。

| 字段 | 判断问题 |
| --- | --- |
| `relevance` | 新闻是否涉及该案例预先定义的主体关系或明确地区范围？提及主体名称、首都或评论别处战事不自动等于相关。 |
| `action` | 该文章是否有范围内、当期已实施/正在实施的常规军事行为报道？武器性能、部署、演习、计划、条件假设及只有否认/争议而没有可确认报道的内容不算。 |
| `threat` | 范围内主体是否实际发出军事威胁？应区分已发生的威胁表态与尚未发生的军事行动，也不能将否认曾威胁计为威胁。 |
| `posture` | 范围内主体是否有已实施或正在实施的部署、动员、演习等姿态变化？只计划部署、否认部署不算。 |
| `cooperation` | 新闻是否报道范围内已经举行或正在进行的协商、会谈？明确协商意向保留为 03 类计划候选，但不计入 v5 的当期历史信号；否认会谈及未被相关主体采纳的第三方建议也不算。 |

`relevance=false` 时其余四项必须为 `false`。事件判断以原文中的施事、受事、地点、发生时间、断言来源为依据；建议在 `notes` 中记录这些字段及歧义。当前分类器将明确距报道日超过七天的行为视为历史候选；评审须采用预先固定的同一口径，不能根据模型表现临时修改。发生日与报道日必须分开；无法核实具体日期就记录“不明”，不能编造日期。

跨句否认、转述、对事件责任的否认与对事件发生的否认要分别审阅；同一篇新闻也可能同时包含争议说法和有独立依据的行为报道。不要因为出现 `disputed` 等单词就给整篇判负。

## 审核记录与裁决

建议由两名审核者先独立阅读，初次审核时不展示模型预测。每人的记录保留在 `reviews` 数组，包含：

```json
{
  "reviewer_type": "human",
  "reviewer_id": "实际审核者的稳定标识",
  "completed_at": "实际审核时间（含时区的ISO格式）",
  "labels": {"relevance": true, "action": false, "threat": false, "posture": false, "cooperation": false},
  "evidence_quotes": ["支持判断的原文片段；不可编造"],
  "notes": "主体、行为、对象、时间与断言判断依据，以及任何分歧"
}
```

上面的值只说明结构，不能原样当作真实审核记录。程序会验证原文引句和完整字段，但不能核验身份或证明某个人确实完成了阅读；不能让 AI 自填 `reviewer_type: human`。

- 没有审核：`review_status: pending`，`labels: null`。
- 一名具名人工完成、或多名人工结论一致：可标为 `human-reviewed`，顶层 `labels` 必须与审核意见一致。报告会明确区分单人和多人审阅数量，单人审核不等于高质量金标准。
- 两人不同意：标为 `needs_adjudication`，保留各自原始意见，不得用多数票或模型输出静默覆盖。
- 完成裁决：标为 `adjudicated`，至少保留两名独立审核者的记录，在 `adjudication` 填入同结构的人工裁决、理由及时间；顶层 `labels` 与裁决一致。推荐由第三人裁决。

所有正事件标签必须附原文证据。评估脚本拒绝冒充已完成的空记录、模型类型审核、缺失字段、相互冲突却未裁决的记录以及不在原文中的引句。

## 指标和下一步

评估分别报告相关性、行动、威胁、姿态和协商的 TP/TN/FP/FN、precision、recall、F1、accuracy。分母为零时指标返回 `null`，不能当作满分。未审核和未裁决项全部排除，绝不自动当负例；报告包含总体与每案例审核覆盖、单人/多人比例。只完成少量容易样本时，不应宣传子集成绩为全集准确率。

这个规模适合发现错误类型，尚不足以可靠估计跨地区、跨媒体的泛化性能。后续应增加普通时期、低报道地区、多媒体来源，以及完整事件级标注（施事/受事/地点/时间/断言）。模型迭代只能在开发部分进行，最终保留测试的标签和样本必须事先冻结，不能跟着检测器改变。
