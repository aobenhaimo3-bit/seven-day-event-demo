# 七日事件预测实验台

一个可在本机运行的计算社会科学研究 Demo：导入带日期的英文新闻，提取 CAMEO 行为候选、查看证据时间线，估计未来七天是否会出现军事行动报道。

**当前输出是新闻报道代理概率，尚不是经过独立真值验证的真实事件发生概率。** 当前 v8 继续修复军事威胁和协商漏报并控制误报：固定 179 条开发记录上，相对 v7 的两类漏报从 14/15 降为 8/8，误报从 1/3 降为 0/1；逐条比较没有新增误报。五项完全一致率由 57.54% 升至 64.80%。预测 Brier 小幅下降，Log loss 略升，分类准确率不变，不能称为整体预测改善。这个项目用于展示研究流程、检查证据和改进方法。

## 运行

安装 Node.js 22 或更新版本。可以在 GitHub 的 **Code → Download ZIP** 下载并解压；在包含 `README.md` 和 `server.mjs` 的目录打开终端。运行 `node --version` 应能显示版本。

只体验已有模型时，执行：

```sh
node scripts/prepare-input.mjs
node server.mjs
```

打开 <http://127.0.0.1:8766/>。不需要第三方运行依赖或大模型 API 密钥，也无需先执行训练。端口可用 `node server.mjs --port 8767` 修改。安装了 npm 时，也可使用 `npm start`。

仓库自带冻结模型参数和老师提供的三个原始数据文件（约49.5 MB）。准备脚本默认将S021–S030合并为10个无标签项目测试案例，写入被Git忽略的`local-data/test_input.jsonl`；该步骤不重新训练。也可使用页面的“选择本地文件”导入自己的JSON / JSONL。数据来源、字段和原字节校验值见[datasets/README.md](datasets/README.md)。

这些原始数据不是现成的未来七天真实冲突标签。原包本轮任务是案例—新闻相关性`yes/no`标注，标签原待填写；本项目的固定测试案例也不等于独立事件真值。当前实验实际使用的150条训练试标和主体别名收录于[research/](research/README.md)，保留待复核标记；课程账号、课件及测试答案不在仓库中。用户另外导入的内容只在本机服务中处理，不会自动上传GitHub。

可用`node scripts/prepare-input.mjs --all`准备全部30例，或`node scripts/prepare-input.mjs --case S021`只准备一个案例。前者保留本项目15个训练、5个验证、10个测试案例的展示标记，仍不会训练模型。若服务已运行，请在准备输入后重启。也可不准备自带案例，直接启动空工作区自行导入。

本项目是 Node.js 本地服务，不能仅靠 GitHub Pages 运行预测后端。

## 从原始数据完整复现一次

这条流程使用仓库中的原始数据和已保存的训练银标，不需要作者电脑上的其他文件或 GPT API。它复现当前报道代理实验，包括开发数据划分、标注审阅入口、模型训练、验证选参、批量测试预测和 Demo。

```sh
node scripts/prepare-development.mjs
node scripts/prepare-input.mjs
node build-model.mjs
node scripts/predict-batch.mjs
node scripts/prepare-evaluation.mjs
node scripts/evaluate-recognition.mjs
node --test
node server.mjs
```

执行后打开 <http://127.0.0.1:8766/>。顺序和产物如下：

| 步骤 | 做什么 | 产物 |
| --- | --- | --- |
| 准备开发数据 | 固定15/5/10案例划分，按较晚集合优先清理跨集重复新闻，复制已保存的训练试标和主体别名 | `local-data/train_pairs.jsonl`、`validation_pairs.jsonl`、`annotations.jsonl`、`case_aliases.json` |
| 准备测试输入 | 从原始数据生成S021–S030的10个无标签案例 | `local-data/test_input.jsonl` |
| 训练与验证 | 训练事件检测器，构造历史窗口与未来七天报道代理标签，在验证集选择正则参数，再拟合最终模型 | `artifacts/research-model.json`、`artifacts/model-report.json` |
| 批量测试预测 | 固定模型对测试案例逐一预测，不再拟合或读取答案 | `local-data/predictions/test-predictions.jsonl`、`summary.json` |
| 准备识别评估 | 按案例和日期固定抽取 60 篇开发新闻，保留人工审核记录；无人工标签时不计算成绩 | `local-data/evaluation/review.jsonl`、`recognition-report.json` |

| Demo | 选择案例、修改截止日、检查证据并导出结果 | 浏览器中的交互结果 |

开发数据预期为训练8,366对、验证1,042对；测试输入为10例、3,670条关联。26个跨集合新闻编号对应27条被排除的较早组合。这里仅利用测试集合的新闻编号隔离重复输入，测试正文、标签和答案不用于拟合或参数选择。

标注步骤复用实际保存的GPT/Codex试标。可先打开 `research/annotations.jsonl`，对照原新闻审阅和修改，再从第一条命令重新执行；程序不会冒充人工复核，也不会自动重新调用GPT标注。`uncertain`和`review_required`仍需人工判断。

批量预测中，历史覆盖不足的案例会保留拒答原因，而非强行给出数字。测试预测文件不等于测试准确率报告：当前未提供未来七天真实事件金标签，程序不会虚构该成绩。验证指标仍只针对报道代理。

GitHub自动检查会在干净环境中实际执行上述准备、重训、批量预测和测试步骤，最后检查前端脚本语法。网页服务最后一条命令会持续运行，可用Ctrl+C停止；端口被占用时使用 `node server.mjs --port 8767`。

## 输入和操作

1. 使用准备脚本生成的项目案例，或下载页面中的**格式模板**，填入自己有权使用的新闻。模板的 `news: []` 为空，不是演示数据或预测样本。
2. JSON 可为单个案例或案例数组；JSONL 每行一个完整案例。每批最多 60 个案例、文件最多 25 MB。
3. 选择截止日，运行预测。只有截止日及以前的新闻进入识别和特征，之后的新闻会被排除。
4. 检查候选事件、原文、历史信号和覆盖情况，导出完整结果 JSON。

格式结构如下，字段中的说明文字应替换成自己的真实输入：

```json
{
  "case_id": "YOUR_CASE_ID",
  "countries_regions": "研究对象",
  "target_situation": "事先确定的研究范围",
  "news_start": "2025-06-01",
  "news_end": "2025-08-31",
  "actors": ["English actor alias"],
  "news": []
}
```

`news` 中每项需要 `news_id`（案例内唯一）、`date`（YYYY-MM-DD）、`title`、`text` 和可选的 `publisher`。日期必须位于案例范围内。未知案例须配置 `actors` 英文主体别名，避免把任意新闻默认为相关局势。`outcome`、`gold` 或旧版预测结果不能作为新闻输入。

模型主要针对英文新闻。数值预测至少需要 28 天可用历史、10 篇去除全文重复后与研究对象相关的新闻，以及近 28 天至少 3 个有相关报道的日期；最近一篇相关且不重复的新闻距截止日不得超过 7 天，截止日也不能早于模型训练信息截止日。无关新闻和完全相同的转载不能补足覆盖或刷新时效。当前冻结模型训练信息截至 **2025-05-01**，更早的回放仅展示历史证据。

## 方法和边界

- 事件识别使用原研究 150 条训练试标产生的词汇统计与保守规则，展示为自动候选。文章、证据句及局部行动片段分别检查研究范围，评论者不自动作为交战方，同一主体及其首都不当作两个主体。按行动、威胁、姿态和协商分别判断否定、计划及争议；相邻句明确否认可使候选转为待复核。计划、假设、历史回顾、演习、武器部署和性能介绍不直接算作当期军事行动。规则并非完整的语义或指代解析，试标仍需人工复核。
- CAMEO 19 军事行动报道是当前预测目标；13 威胁、15 军事姿态、03/04 协商是历史信号，不分别输出事件发生概率。
- 历史特征包含近 7 / 28 天相关报道覆盖、行动报道比例、威胁和协商等变化，概率模型采用带正则的逻辑回归。计数、比例分母、时间线和训练/推断准入均只使用相关且已配置研究范围的非重复新闻。全文经过字符、大小写和空白规范化后去重，保留最早报道；尚未实现近似改写去重或事件聚类。导出结果提供原始篇数、无关及重复排除数、最近相关报道距截止日的天数。
- 训练标签来自随后七天的冻结检测器输出。未检测到军事行动报道，不代表现实中没有军事行动；原文中的实际发生日期未自动核实，时间线采用报道日期。
- 原始案例为约三个月片段。滚动训练使用 **28–92 天**可用历史，没有把每个训练锚点都视为拥有完整三个月历史。
- 仅未来七天至少三个日期有相关新闻的历史窗口参与训练，存在报道覆盖筛选偏差。未来报道数不进入推断特征或运行时预测条件。
- 验证集选择正则强度，随后将训练与合格验证窗口合并拟合最终模型。验证指标来自合并前的选择阶段，不是独立测试成绩。测试输入和答案不用于拟合或选参数。
- 当前冻结模型有 **70 个训练窗口、14 个验证窗口**，分别来自 10 个和 3 个有效案例。验证 Brier 为 **0.073717**，常数报道率基线为 **0.123870**，上一周延续基线为 **0.071429**。数值越低越好；本次优于常数基线，仍略差于延续基线，没有足够独立案例支持显著性或泛化结论。窗口间有关联，部分研究对象间有重复报道，不能把窗口数量当作同等数量的独立案例。
- 部分原研究案例采用较宽的区域研究范围，不能把区域军事行动报道解释为严格双边开战预测。同一现实事件也可能被多篇报道重复记录。

`probability.real_event_probability` 始终保持 `null`。尚无完整独立未来事件真值、普通时期负样本和概率校准，不能据此声称已经验证真实冲突预测能力。

## 第一轮修复记录：v4

本轮保留原始数据、试标、主体别名、15/5/10 案例划分、14 个特征及正则参数候选不变，更新事件规则为 `scoped-assertion-v4`，重新训练并生成冻结模型。新增 14 项回归测试，全部 35 项测试通过；三个真实训练新闻误判（P3N00027、P3N00214、P3N02560）均不再计入俄乌行动信号。检查用的纯足球新闻输入不再产生军事行动概率。推荐链接清理、证据句范围、同年历史日期、否认、演习、武器性能及无关新闻对特征和未来覆盖的影响都有检查。

相关覆盖过滤使训练窗口从 105 降到 70，验证窗口从 22 降到 14。各版原生验证 Brier 从 0.101094 变为 0.095961，但样本和标签发生变化，不能据此断言预测改善。两版共同保留的 14 个窗口中，有 2 个代理标签改变。固定这 14 个窗口、统一采用新版标签，使用各版仅在训练集拟合的模型对比：

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| Brier（越低越好） | 0.092922 | 0.095961 |
| Log loss（越低越好） | 0.297135 | 0.318185 |
| 准确率 | 85.71% | 92.86% |
| 假阳性 / 假阴性 | 2 / 0 | 0 / 1 |

第一轮已知识别和覆盖错误得到修复，分类错误减少；概率误差没有改善。上述标签仍由检测器生成，验证集仍用于选参，不能当作独立真值测试或统计显著的泛化结论。本段记录的是 v4，当时尚未修复的主体关系、跨句否认、日期和覆盖时效问题继续在下一轮处理。

第一轮完整报告保留在 [research/validation-comparison-v4.json](research/validation-comparison-v4.json)。

## 第二轮修复验证：v5（2026-11-04）

本轮继续保留原始数据、训练试标、主体别名、案例划分、14 个特征及正则候选网格不变，规则版本为 `event-context-coverage-v5`。完成以下改动，并通过全部 **82 项测试**：

1. **主体关系**：行动范围排除讨论者、转述者和事后评论者；保留局部施事、行为、对象候选及判定依据，断言状态绑定同一动作，避免借用其他行动的肯定状态。支持简单转述和明确指代，不宣称完整关系抽取。
2. **断言与否定**：分别处理行动、姿态、威胁和协商，否认部署、未举行会谈不再计入信号；争议地名形容词不会自动否定行动，紧邻的明确否认可使报道转为待复核。计划会谈仅保留为意向候选。
3. **时间**：支持英文月日/日月、序数、缩写、年月、相对日期及跨年；明确未来日期不计入当前行动，冲突或无效时间证据进入复核。解析引用日期，不把它冒充已核实的实际发生日。
4. **覆盖质量**：正文规范化去重，同文更换 ID、来源、标题或日期不能增加篇数或刷新报道时效；无关副本不能挤掉有效记录。最近相关非重复新闻超过七天拒绝数值预测，训练与推断使用相同历史门槛。
5. **评估基础**：固定抽取 60 篇开发新闻，建立人工审核、分歧裁决、原文校验和混淆矩阵工具。当前 60 篇全部待人工审核，报告为 `not_evaluable`、`metrics: null`，没有虚构识别准确率。

重新训练后仍有 70 个训练窗口、14 个验证窗口。对比冻结的 v4 引擎时，只在训练集拟合权重；两版均在原网格中用验证集选参（均为 50），不使用合并验证集后的部署权重。以下比较的 14 个窗口完全相同，验证标签也完全相同：

| 指标 | v4 | v5 |
| --- | ---: | ---: |
| Brier（越低越好） | 0.095961 | 0.073717 |
| Log loss（越低越好） | 0.318185 | 0.265990 |
| 准确率（0.5 阈值） | 92.86%（13/14） | 100%（14/14） |
| 假阳性 / 假阴性 | 0 / 1 | 0 / 0 |

**本次概率误差和分类结果均优于 v4，但概率误差仍未超过延续基线。** 14/14 只是小规模开发验证中对报道代理标签的结果，不是独立真实事件成绩。批量预测的 10 个无标签测试案例有 9 个满足输出条件、1 个拒答；这也不是准确率。未来仍需补充跨媒体、普通时期样本和独立未来事件真值，不能通过更多规则或重训代替这些数据工作。

完整对比见 [research/validation-comparison.json](research/validation-comparison.json)，人工审阅方法与标签格式见 [research/evaluation-protocol.md](research/evaluation-protocol.md)。60 篇样本来自已经用于开发的验证案例，人工审阅完成后仍应称为开发阶段识别评估，不能冒称未接触过的独立测试。

仓库保存了带固定哈希的 v4 引擎及 v5、v6、v7 完整快照，不依赖旧 Git 对象。历史报告保留；当前源码的重训与 v7 → v8 比较使用：

```sh
node scripts/prepare-development.mjs
node build-model.mjs
node scripts/compare-validation-v8.mjs
node --test
```

脚本从 `research/baselines/` 读取已校验的旧版引擎，不联网，不读取测试输入或答案。历史比较脚本要求对应的模型版本，拒绝覆盖旧报告。服务同时检查规则版本和十个识别模块的源码哈希；模型与规则混用会被拒绝，需重新训练。规则哈希统一换行符，冻结快照文件按原字节保留。

## 使用自己的数据重训

上述完整复现命令已准备当前实验所需的全部文件。若要换用自己的数据，可按相同格式替换已被Git忽略的 `local-data/`：

```text
local-data/
  train_pairs.jsonl
  validation_pairs.jsonl
  annotations.jsonl
  case_aliases.json
  test_input.jsonl       # 可选，仅用于页面预览，不参与训练
```

训练/验证 pair 每行是 `{ "pair_id": "...", "split": "train或validation", "case": { "case_id": "...", "news_start": "...", "news_end": "..." }, "news": { "news_id": "...", "date": "...", "title": "...", "text": "...", "publisher": "..." } }`。

试标每行是 `{ "pair_id": "匹配训练pair", "split": "train", "relevance": "yes或no或uncertain", "events": [{ "cameo_code": "194", "evidence_quote": "训练新闻中的原文证据" }] }`。未知或争议事实应保留复核状态。主体别名文件结构为 `{ "cases": { "案例ID": { "strong": ["英文别名"], "groups": [["主体一别名"], ["主体二别名"]], "context": ["上下文词"] } } }`。

```sh
node build-model.mjs
```

此命令用本地开发集替换 `artifacts/` 中的模型和聚合报告；不读取测试输入或测试答案。如果四个开发数据文件均存在，服务启动时会校验它们与冻结模型中的来源哈希。不要提交这些本地文件；重新发布训练产物前也应检查是否包含不应公开的信息。

当前仓库包含原始新闻、训练银标、主体别名及开发数据重建脚本，可从下载文件完整复现本版计算流程。它不会复现一次新的人工标注过程，也不包含尚未建立的真实未来事件金标签。
